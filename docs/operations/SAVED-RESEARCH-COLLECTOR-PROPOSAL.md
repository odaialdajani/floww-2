# Saved-research collector proposal

This is a review proposal, not installation or execution authority. Research remains
uninstalled and unscheduled until independent source review and one explicitly
admitted real native research/audit pair produce accepted copied facts. The prior
two-POST failure stays parked and is not relabeled by offline tests.

The proposed collector runs `ops/research_worker.py run-once` through the verified
system Python 3.9 interpreter (`/usr/bin/python3` on this host), with a finite
launchd interval, no KeepAlive, no notifications and no automatic resume. A
300-second interval is a proposed saved-data check cadence, not a model-call
cadence. It only reads the existing fixed saved-observation GET routes. Stable
observation IDs prevent polling and receipt-time age changes from spending again.
No quote refresh, tool dispatch, strategy, account action or order is exposed.

Before any native role, the full original saved-page envelope is validated and
the full packet retained. Both independent roles receive the same deterministic
view: original packet/source/decision identity, at most three observation IDs,
contract/provider/scope, bid value/unit/status, and the original receipt and bid
clock objects. Missing and stale labels survive. Other prices and historical
structure are omitted. At least one exact bid fact is required; the original full
packet independently checks every value, unit and citation. Only selected bid
facts are accepted. Acceptance remains retrospective and nonexecutable.

All caller state directories share the fixed private
`~/Library/Application Support/FLOWW/operations/research-admission/admission.json`
and one exclusive admission lease held for the entire pair. Lock and directory inode identities are
checked before reservation, before and after each role and before finalization;
replacement fails closed without rebinding the lease. Symlinks, foreign-owned
files and hardlinks are refused. The ledger prepays
each new pair before native work. The conservative default is four new pairs per
UTC day, including failed and interrupted pairs. The persisted `daily_pair_limit`
may be lowered to 1..4; values outside that range fail closed. These defaults are
local operating limits, not NVIDIA quota claims. A pair admits at most one POST
per role, with no model/endpoint switch, polling, automatic retry, thinking
parameter guess or output-cap increase.

Any pair failure parks every new input globally until the explicit operator
`resume-circuit` action. A durable unfinished attempt also parks new calls after
restart. Ordinary worker `resume`, a different state directory, changed evidence,
a source-rule change or midnight does not clear that circuit. `resume-circuit`
preserves all prepaid budgets and dedupe records; it grants no source acceptance
and does not resume a paused worker.

Local receipts stop at their existing capacity pending manual archival. The
shared ledger never automatically discards dedupe IDs; its finite 1024-identity
capacity parks new work for explicit review. Archiving local receipts cannot
release global dedupe. The admission ledger must be preserved with any manual
state migration; deleting or editing it is an explicit operator intervention,
not supported retention. A backwards admission date is refused.

Receipts keep bounded status, transport error class, finish reason, usage, request
byte count and message-character count. Raw native prose, headers and credentials
are excluded; cost stays unknown unless established independently. The native
profiles retain empty tools, no memory/context/session database, SDK retries zero,
native total attempts one, auto recovery zero, max iterations one, and a 1024-token
output cap. Independent HTTP counting remains necessary because native recovery
can attempt a follow-up despite nominal retry settings.

Before scheduling, the integrator must freeze and independently review the exact
source/wire envelope, separately admit the fresh two-POST trial, inspect both
closed validation receipts and all native diagnostics, and then approve the
installed source hashes, shared ledger, pause controls and launchd configuration.
A successful retrospective pair does not establish fresh coverage, trading value,
venue permission or an execution policy.
