# Four-agent next wave — evidence before expansion

## Boot and admission

Exactly four sessions; requested Muse Spark 1.3 MAX is not a verified model ID.
Use only owner-approved provider/model configurations. Record actual limits.
Agent 1 boots first, reads the v4 checkpoints without overwriting them, fetches
main and verifies INTEGRATION.md's candidate ancestry plus PR65 state/checks.
If integration is incomplete, finish that exact unit before new product work.
Agent 4 boots second. Builders receive one explicit path-leased card each.
No automatic admission follows from the candidate list below.

Agent 1 owns the sole active manifest and launch pointer; never maintain two
competing current-state files. Runtime root is specified in README. Provision
four lane directories only after inspecting existing state. Each boot/checkpoint
records task, full base/head, branch/worktree, allowed paths, actual model,
dirty ownership, evidence, last command/result and one exact next command.
Do not label a template, historical checkpoint or announced task as running.

## Bounded candidates, in priority order

1. **Backend data provenance and units audit (Agent 2, read-only first).**
   Inventory only providers and datasets actually configured in source/contracts,
   without printing credentials or calling paid/live endpoints. Trace each
   admitted signal's producer -> normalized payload -> storage -> consumer.
   Deliver a table with evidence paths, source field, event/receive/revision time,
   exact instrument identity, units, sampling frequency, missing/stale behavior,
   entitlement uncertainty and observed/proxy/model classification. Unknowns stay
   unknown. Select one demonstrated contract defect for a later repair card;
   do not invent a broad data platform or wire an unlicensed source.
2. **Mounted alert namespace contract (Agent 3).** Start with read-only tracing
   of alertEngineBadges and /api/alerts/{ticker} versus the persisted alert feed.
   Prove which producer and consumer are live. Propose one bounded mounted UI
   unit if the gap remains. A builder card must pin response shape, loading,
   empty/error/stale/ticker-switch behavior and accessible rendered output.
   Preserve App.js freeze. No new endpoint or backend changes inside this lease.
   Sweep filtering and viewport work are separate unimplemented candidates;
   never bundle them to manufacture more output.
3. **Execution recovery audit (Agent 4 reviewing Agent-2 follow-up).** Challenge
   crash before/after broker acknowledgement, restart, duplicate delivery,
   partial fills, canceled/rejected orders, changed journal rows and option
   identity. Use real temporary storage and mocked broker transport. The new
   exception endpoint is not an operator resolution policy. Any resolution tool
   needs an explicit audit-trail/authorization contract and evidence of identity;
   never auto-close ambiguous legacy cards. No live orders or journal migration.
4. **Evaluation evidence (Agent 2 after provenance).** Inspect the existing
   event-envelope/eval harness from merged PR59/60. Propose one executable test
   for a demonstrated point-in-time or units defect. A research proposal must
   predeclare horizon, label availability, split, purging/embargo, benchmark,
   costs/latency, uncertainty and rejection criteria. No threshold/weight tuning
   on the holdout, no profitability claim from unit tests or synthetic fixtures.

Agent 4 independently reviews each admitted product candidate at its full SHA.
Agent 1 alone integrates after tests and review; green CI is necessary, not
proof of financial truth. Record rejected hypotheses and unverified sources.

## Output and stopping contract

Optimize for accepted, tested units, not token volume or permanent activity.
One card produces one bounded diff or a falsifiable no-change finding with
file/line evidence. No unsolicited refactors, dependencies or provider changes.
Checkpoint at RED, GREEN, commit, push and review; use short resumable context.
After two unchanged checks, choose an admitted task or park. Credit exhaustion
parks with a checkpoint; it never triggers fabricated completion or nested
fallback loops. A multi-day schedule requires separately approved native task
configuration; this package does not claim a scheduler is running.

Final per-unit receipt: exact base/head; changed paths; RED/GREEN commands and
exit results; CI links; independent verdict; remote verification; limitations;
remaining owned dirt; one next command. Coordinator records merge SHA and
post-fetch candidate ancestry. Preserve all archival work until separately
reviewed; do not equate a clean working tree with delivered functionality.
